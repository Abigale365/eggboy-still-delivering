## 二、问题

被留下的东西没人替它们收信。搬去新城的人带走了能带走的，留下烤炉、狗、灯塔——它们还在等。《寄给不在的人》用"送信—涨水"把这件事做成一个 7 分钟的仪式：每送到一封信，海水涨一截，路变短，镇子变小。

## 三、产品方案与实际交付对齐（第 3 章）

产品方案（v4）定义三层结构。逐层对齐如下：

### 3.1 叙事层——【已完成】

| 方案设计 | 实际交付 | 差异说明 |
|---|---|---|
| 序章 30 秒：开机、取信、教操作 | 开场预览机位 4.7 s 落到角色身后，取信 6.7 s（<30 s 达标） | storyaudit intro/pickup 全过 |
| 面包店 1.5 分钟：火柴→柴火→装炉→点火，烟飘向山那边 | 全链实现，烟囱粒子可见，水位 L1，邮戳 1/3 | audit 计时 88.9 s 为加速值 |
| 学校 2 分钟：找球、放回碗、逐行读信、小黑跟随 | 拖鞋→红球归碗→逐行 5/5→sad→curious→happy，邮戳 2/3，水位 L2 | 逐行读信实测通过 |
| 灯塔 2 分钟：踩木箱、油壶爬塔、点灯、山那边回应 | 全链实现：天光 20 s 转暗、光束扫海、40 个手电回应，邮戳 3/3，水位 L3 | reply_lights=40 |
| 结局 1.5 分钟：写给 EGGBOY 的信、回望、字幕 | 下塔、老周的信（惊讶→笑）、回望镜头、水位 L4、新城灯光、字幕"所有的信，都送到了。" | 22 步全过 |
| 玩法克制：移动/靠近高亮/单手拿/读信/邮戳/涨水 | 完全一致，未加多余机制 | routeaudit 28/28 |

## 四、Aholo 技术栈怎么用（评分权重 30%）

### 4.1 流水线总览

```
输入参考图（四视图 PNG）
   → Lux3D 生成 GLB（网页版，统一风格关键词）
   → Blender/脚本"手术刀"精修（修面、材质、烘焙、减面试验）
   → Unity glTFast 导入 → prefab → IslandBuilder 白盒场景
   → story/route/map/water/scan 自动审计 → Windows + WebGL 构建
```

## 六、生态价值（新物种奖视角）

1. **可继续生长的入口**：模型来源抽象为 `IModelProvider`——今天送信的是 Lux3D 生成的 41 件资产，明天可以是任何用户上传的照片重建件；`Features.scan` 一个开关切换。
2. **数据飞轮的真实一环**：41 件资产的"输入图→原版→精修→入工程"全程留痕（每个 lux3d-* 目录含 original/ 与精修记录），本身就是可复用的 Lux3D 工作流数据集。
3. **自动化验收流水线可复用**：story/route/map/water/scan 五类审计 + 项目锁 + 证据目录结构，可直接套到任何 Lux3D 资产组装的项目上。
