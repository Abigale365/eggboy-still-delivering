# 《寄给不在的人》工程书

版本 1.0 · 2026-11-06 · 比赛截止 2026-11-19 19:00（北京时间）

这份文档写给接手这个工程的 agent 和两位队员。照着它从头做到尾，就能交出一个能完整玩的游戏。

## 0. 接手的 agent 先读这一节

### 0.1 目标

**把游戏做出来。** 玩家操作 EGGBOY，从序章走到结局字幕，约 7 分钟，画面像预览图，能在网页上打开。

优先顺序，冲突时上面的赢：

1. 能玩通：序章、面包店、学校和小黑、灯塔、结局。
2. 画面像预览图。
3. 能交：网页版、报告、视频。
4. 扫描和打印：**只留接口**（WP-09）。11/14 决策点通过后才可能接真实功能。

### 0.2 工作循环

每次开工都这样做：

1. 读 `docs/progress.md`，再看 `git log --oneline -10`，弄清做到哪了。
2. 选第一个状态为 `todo`、依赖都已 `done` 的工作包（第 8 节）。
3. 把它改成 `doing`，写上你的名字和时间，提交。
4. 做事。每改一块就编译或构建一次，别攒到最后。
5. 跑完“验收”一栏的每一条，证据存到 `docs/evidence/<WP编号>/`。
6. 全过才改成 `done`，提交，提交信息以 `[WP-xx]` 开头。
7. 回到第 1 步。

做不下去时按 0.4 处理，不要停在原地等人。

### 0.3 铁律

违反任何一条都要停下，写进 `docs/human-queue.md`。

1. **不花积分。** 不经用户这一次的明确同意，不调用任何会花积分的 Lux3D 接口，不给 `lux3d.mjs` 加 `--confirm`。先写生成单到 `docs/orders/`，用占位素材继续开工。
2. **不从零重建 Lux3D 素材。** 精修只做小手术，规矩见 `lux3d-asset-refine` skill。减面、调色、定尺寸可以做；替换部件要先问。
3. **不碰角色手感。** `EggboyPlayer`、`EggboyGait`、`EggboyPose`、`EggboyAntiClip`、`EggboyFace*` 的常量和调用顺序不改。需要新能力就加新方法，再跑回归。
4. **不跑旧生成器。** `ExpandedTownBuilder` 的 `Build`、`BuildWindows`、`BuildWebGL`、`BuildPreviews` 都不要调用，它们会覆盖场景。
5. **不在外层仓库提交。** `Documents\ChatGPT\3d黑客松` 是一个还没有任何提交的 git 仓库，`outputs` 也没被忽略，在那里 `git add` 会把几十 GB 加进去。只在 `UnityProject` 自己的仓库里提交（WP-00 建）。
6. **不动别人的目录。** `outputs` 下其他文件夹只读。`outputs.__migration_backup_20261106T041515` 不要碰。
7. **不说没做到的事。** “已生成”“已验证”“已验收”是三种状态。没运行过就写没运行过。没打印过，任何材料都不能写“已成功打印”。
8. **对外的事要问。** 发帖、部署到公网、提交比赛、下载第三方文件，都要用户明确同意。
9. **同一时间只开一个 Unity。** 工程被占用（`Temp/UnityLockfile` 存在且有 Unity 进程）时不要启动第二个。同一时间只有一个 agent 改 `TideTown_Main.unity`。

### 0.4 卡住时怎么办

| 情况 | 做法 |
|---|---|
| 需要用户决定或同意 | 写进 `docs/human-queue.md`，用默认值或占位继续，换下一个工作包 |
| 同一个问题、同一个思路连试 3 次没改善 | 停止这个思路，用工作包里的“来不及时”方案，把情况写进 `docs/progress.md` |
| 看图才能判断好坏 | 存对比图，写进 human-queue。自己看过只算“已验证”，不算“已验收”。不是决策点就不阻塞 |
| Unity 被占用，或许可证报错 | 写进 human-queue，先做不需要 Unity 的工作包 |
| 工作包超过预计时间一倍 | 用“来不及时”方案收尾，继续往下走 |

## 1. 范围

**要做：** 第 4 节的全部玩法；预览图的布局和质感；约 7 分钟的完整流程；Windows 和网页两个包；声音；存档；报告和视频需要的素材。

**不做：** 建筑室内；NPC；昼夜循环（灯塔那段天色变暗除外）；手机端；多人；可驾驶的船；手柄适配。大纲写了手柄，这里砍掉，键盘鼠标优先。

**只留接口：** 扫描、运行时加载模型、打印。

## 4. 故事和玩法规格

路线：山口邮筒 → 邮局 → 面包店 → 学校 → 船棚 → 码头 → 灯塔 → 回邮局 → 上山。

### 4.1 通用机制

| 机制 | 规格 |
|---|---|
| 移动 | 默认走路，按住 Shift 跑，和现有操作一样。全程走路约 4.5 分钟，跑约 1.5 分钟。WP-15 测出总时长超过 9 分钟，才加“按住 0.8 秒自动小跑”，且只改 `run` 参数，不改速度常量 |
| 互动 | 靠近 1.4 米内发光并显示提示，按 E |
| 随身物品 | 一次一件。邮包图标显示当前物品。按 E 放到合法位置 |
| 读信 | 信纸铺满屏幕，E、回车或点击收起。读信时锁定角色 |
| 回忆线索 | 靠近物件冒一句话，3 秒消失，每件只冒一次，可以再按 E 重看 |
| 邮戳 | 明信片上三个格，每送到一封盖一个 |
| 海水 | 每站结束涨一截，带 4 秒过场，见 5.4 |
| 掉队保护 | 掉进水或卡住 3 秒，回到最近的安全点，不算失败 |
| 目标提示 | 屏幕上方一行（`EggboyUI.SetGoal`） |
| 存档 | 每完成一步自动存。重开回到这一步的起点 |

## 5. 世界规格

### 5.1 世界透过一个固定机位来搭

预览图是斜着俯视的，高的东西在图上会往上偏，远处也被压扁，不能把像素直接换算成平面坐标。**所有位置都要经过下面这个机位换算。**

机位叫 `PreviewCam`，写在 `Data/preview_camera.json`。不用反推原图的真实相机：我们自己规定一个机位，再让世界在这个机位里和预览图重合。

| 参数 | 值 |
|---|---|
| 分辨率 | 1774 × 887，和预览图一样 |
| 垂直视场角 | 20° |
| 俯角 | 35°，Unity 旋转 `Euler(35, 0, 0)` |
| 位置 | (0.00, 52.05, -70.05) |
| 画面中心 | 对着 (0, 3, 0) |
| 主街高度上的比例 | 约 0.034 米/像素 |

**方向：** 1 单位 = 1 米。Y 向上，X 向东（图右），**Z 向北（图上）**。旧场景正好和预览图左右相反，那种方向进 Unity 会得到镜像的画面，新场景不要沿用。

**全镇只用一个比例。** 建筑、路宽和点位都按这个机位来，不要单独放大或缩小街道。

从图上一点 (u, v) 和它的设计高度 Y 求世界坐标：

```
f = 443.5 / tan(10°) = 2515.2
C = (0.00, 52.05, -70.05)
F = (0, -sin35°, cos35°)    R = (1, 0, 0)    U = (0, cos35°, sin35°)
D = F·f + R·(u - 887) + U·(443.5 - v)
k = (Y - C.y) / D.y
世界X = C.x + D.x·k
世界Z = C.z + D.z·k
```

### 5.4 水位

海面 Y 由 `WaterLevel.Set(y, 秒)` 平滑改变，所有依赖水位的东西读 `WaterLevel.Y`。

| 档 | Y | 时机 | 效果 |
|---|---:|---|---|
| L0 | 0.00 | 开始 | 沙滩完整 |
| L1 | 0.45 | 面包店后 | 沙滩变窄 |
| L2 | 1.15 | 学校后 | 码头（0.9）和低洼段（1.0）被淹，木箱漂起 |
| L3 | 1.60 | 灯塔后 | 船棚（1.4）被淹 |
| L4 | 3.05 | 结局过场 | 主街和邮局台阶被淹，此时玩家已在山路 |

规则：

- `IslandWorld.Walkable` 在 `地面Y < 水位 - 0.05` 时返回 false，玩家走不进水里。
- 不用 `EggboyCollider.water`。
- 木箱是 `top` 碰撞体，`top = 水位 + 0.18`，每帧更新，带 ±3 cm 起伏。间隙不超过 0.25 米，这样**不用跳就能走过去**。

### 5.6 地形做法

**不要用 Unity Terrain，也不要手工雕。** 预览图的地形就是几层平台，崖壁全被石头和灌木盖住。地形分成两层：

- **走的面：** 简单的平台、坡道和台阶坡面，放在 Ground 层，有碰撞。
- **看的面：** 石头、灌木、树、栏杆、路面细节，没有碰撞，只负责好看。

| 分区 | Y | 能走 |
|---|---:|---|
| 海面 | 水位 | 否 |
| 沙滩、礁石滩 | 0.3–0.5 | 沙滩只看 |
| 码头 | 0.9 | 能，L2 后被淹 |
| 低洼段 | 1.0 | 能，L2 后靠木箱 |
| 船棚 | 1.4 | 能 |
| 操场临海角 | 3.0 | 能 |
| 临海步道 | 2.6 | 能 |
| 主街、操场 | 3.0 | 能 |
| 邮局后院、学校后门 | 3.4 | 能 |
| 灯塔台 | 5.0 | 能 |
| 住宅层 | 5.5 | 第一版只看，时间够再开放 |
| 山路 | 3.0 → 8.5 | 能，用坡面 |
| 塌方 | 9.0 | 否 |

步骤（前三步不需要 Unity）：

1. **描分区：** 在预览图上描每个分区的多边形，存成 `Data/preview_zones.json`，单位是图上像素，每块带 Y。海岸线可以按蓝色阈值自动提取，再人工修。描线时把预览图切成小块、画上带数字的网格再看，比直接估坐标准。
2. **投影：** `tools/preview/unproject.py` 用 5.1 的公式把顶点投到世界，生成 `Data/world_layout.json`。
3. **叠图检查：** 把分区、路网和点位画回预览图，确认贴合。
4. **生成白盒：** `IslandBuilder` 用高度网格生成地形：固定高度的格子直接取分区 Y，没固定高度的格子解拉普拉斯方程得到陡坡，再用石头盖住坡面。加坡道和台阶坡面。只用纯色：海蓝、路沙、草绿、崖棕。
5. **校对：** 从 `PreviewCam` 截图，和预览图半透明叠加。偏了就回第 1 步改多边形，再生成。
6. **最后盖东西：** 轮廓和布局过关后，才开始放圆石、灌木和树。

坡面坡度不超过 30°。高差用坡面做碰撞，台阶只是外观。

### 5.7 还原度验收

agent 判断不了“像不像”，所以预览图的一致性要拆成能量的项目。所有比较都用 `PreviewCam`，分辨率 1774 × 887，由 `tools/preview/score_preview.py` 输出 `score.json`、左右对比图和 50% 叠加图。预览图上的编号和文字标签要从计算中排除。

| 项目 | 量什么 | 合格线 | 什么时候查 |
|---|---|---|---|
| 布局 | 主线点在场景里的实际位置投到画面上，和编号的距离 | 平均不超过 15 像素 | WP-05、WP-06 |
| 轮廓 | 陆地和海的形状重合度（IoU） | 不低于 0.9 | WP-05 |
| 建筑 | 8 栋建筑投到画面上的边框和预览图比 | 位置和大小偏差不超过 10% | WP-05 |
| 色调 | 屋顶、路面、草木、石头、海五类的主色 | ΔE 不超过 12 | WP-17 样板段，WP-19 全镇 |
| 密度 | 植被和石头盖住的面积 | 不低于预览图的 80% | WP-17 样板段，WP-19 全镇 |
| 质感 | 左右对比图和叠加图 | **两位队员判断** | 决策点 11/11，WP-19 |

合格线是起点值。第一次跑完后如果明显不合理，把数字和图写进 human-queue，由用户决定要不要改，agent 不能为了通过自己放宽。

要分清能做到的和做不到的：

- **这个俯视机位**可以做到布局一致。玩家在地面看到的画面，只要求布局、颜色和质感一致。开场、过场和地图都用这个机位，让人一眼认出来。
- **预览图是 AI 画的。** 屋顶卷边这类细节 Lux3D 模型未必有。这种差别只记录，不能为了分数重建模型（铁律 2）。
- 自己量过只算“已验证”。对比图经两位队员看过才算“已验收”。

```csharp
    GameState Load();                    // 没有存档返回 null，版本不符返回 null 并记日志
    void Save(GameState s);
}

public sealed class ControlGate {        // 读信、地图、过场都来取锁，只释放自己的锁
    public object Acquire(string who);
    public void Release(object token);
    public bool Locked { get; }
}
```

`SaveStore` 用 `PlayerPrefs` 存 JSON（Windows 和网页都能用，网页版要调用一次 `PlayerPrefs.Save()`）。

`InteractionService` 负责找最近目标、发光、提示和转发按键。`StoryDirector` 读 `steps.json`，监听互动完成，推进步骤、改目标文字、触发水位和过场。

## 11. 进度文件格式
