### 1.2 v3 普遍的问题（照着这些改）

从代码读出来的共性问题，打磨时逐条消灭：

1. **玩法是弹窗不是世界**：E 透视拓印是一张卡片选模板，按固定倍数放在人前方 3.4 m（`PerspectivePrintSystem.StampPerspectiveIntoWorld`），根本没有透视对齐。G 光影没有真影子，镜头前两个模型转到角度接近 0° 就算赢（`ShadowAndChimeSystem.Update`）；声音部分是 4 个按钮。
2. **Lux3D 名不副实**：心愿造物笺调的是文生图接口 `multimodal-to-image`，生成的图也没用上。真正放出来的是场景里现成的模型，而且对不上号，比如"美食"放出来的是面包篮 `Bakery_basket`，"玩具"是救生圈（`AIAgentCalibrationDirector.SpawnCustomGiftForDog`）。
3. **一步跳关**：揭字"最后一炉暖火"直接把火柴、柴火、木匣三个旗标全设上，然后点火（`WordMaterializerSystem.ApplyThrownWordStoryEffect`），整站谜题被跳过，毫无过程。
4. **残影是假的**：F 只记位置，来回乒乓播放，没有动作；"协力"是按距离写死的特判（`TidalEchoCloneSystem.AssistNearbyStationTask`），并不是残影真的站在踏板上。
5. **文字太多**：到处是 `ShowToast("【危险！正在被狂风吹跑】失衡度…")` 这种说明句，和"纯密室、靠环境"的定位矛盾。
6. **按键冲突、模式键生硬**：数字键 1–4 切"模式"（`AvantGardeGameplayHub`），E 既是互动键又是拓印旋转键，F 同时管小黑、擦盐霜和风箱。
7. **成就表和攻略对不上**：代码里 15 项（`TideTownAchievementSystem.AllAchievements`）的名字和 `邮差密室通关与多解成就全攻略.md` 不一致；E、G 两个方向没有成就。

## 3. 设计原则（所有 WP 通用）

1. **交互在世界里**：玩家看到的变化要发生在 3D 场景中（物体动、光变、声音响、EGGBOY 表情变）。UI 只允许用在三处：读信、打字（心愿造物笺）、成就图鉴。特写机关（旧物端详、木匣）可以用镜头拉近的 3D 特写，但要直接拖拽 3D 部件来操作，不靠 ◀ ▶ 按钮。
2. **功能由场景决定，外观由 Lux3D 决定**：造出来的东西"能干什么"由它在哪、属于哪一类决定，规则写死、可测试；"长什么样"交给 Lux3D。这样实时生成失败也不会卡关。
3. **一题多解，但每种解法都有过程**：替代解法可以更快、更好玩，但不能一步把整站设成完成。改的应该是"获取某个物品 / 打开某个门"，而不是直接改结局旗标。
4. **环境先说话**：线索靠场景和信里的句子给。Toast 只在 WP-03 的最后一层提示里出现。
5. **同一上下文里一个键只干一件事**（统一按键表见 WP-04）。
6. **每个方向都要有自动审计**：在 `InnovationAudit.cs` 里用代码驱动走完一遍，输出通过 / 失败（WP-90）。

### WP-02 Lux3D 网关 + 运行时加载 + 保底库

这是 D 和心愿造物笺的底座，排第一优先级。

**接口（已实测，见 `Documents\say-and-slay\lux3d-test\测试结果.md`，完整规范在同目录 `openapi.json`）**
- 网关 `https://api.aholo3d.cn`，请求头 `Authorization: <key>`（不加 Bearer）。
- 文生 3D：`POST /lux3d/v1/generate/text-to-3d/task/create`，body 字段：`prompt`（必填）、`style`（用 `hand_painted` 或 `cartoon`，和小镇画风一致，两种都试一次再定）、`version: "G1-Turbo"`、`faceCount: 20000`（接口下限 10000）、`outputFormat: ["glb"]`、`enablePbr: true`。
- 查询：`GET /lux3d/v1/generate/task/get?taskid=`，状态 3 成功、4 失败；运行中 `outputs` 里可能有 null，要判空。
- 实测：G1-Turbo 文生约 60 s，图生约 20 s；**并发上限 5**；结果 URL **2 小时过期**，要立刻下载；返回尺寸不可信，朝向不统一；贴图是 2048 PNG，一件 5–11 MB。

**代码结构**（新建 `Assets/TideTown/Runtime/Lux3D/`）
- `ILux3DGateway`：`Submit(Lux3DRequest) → handle`，`Poll(handle) → {state, progress, glbBytes|error}`。
- 三个实现：
  - `DevDirectGateway`：直连 Aholo，只在 `UNITY_EDITOR || DEVELOPMENT_BUILD` 下编译；从 `.env` 读 key；**每次 Submit 都追加一行到 `docs/lux3d-ledger.md`**，到 30 次就拒绝并报错。
  - `RelayGateway`：预留。请求格式先定死：`POST {relayUrl}/lux3d/text-to-3d {prompt, style, faceCount}` → `{taskId}`；`GET {relayUrl}/lux3d/task/{taskId}` → `{status:"running"|"done"|"failed", glbUrl, error}`。转发服务放哪以后再定，现在只写客户端 + 一个本机 node 假服务器 `tools/lux3d-relay-mock.mjs`，返回保底库里的 GLB，用来测。
  - `MockGateway`：开发和审计默认用它。可配置延迟（默认 8 s）和失败率，返回保底库里语义最接近的 GLB。
- 选择方式：`StreamingAssets/lux3d.json` 里写 `{ "mode": "mock|dev-direct|relay|offline", "relayUrl": "", "maxPerSession": 6, "timeoutSec": 150 }`。发布包默认 `offline`；relay 地址定了以后改成 `relay`。
- `Lux3DJobQueue`：同时最多 4 个任务（留 1 个余量给并发上限）；超时或失败 → 状态改为"用保底"，不再重试，不扣第二次。
- `RuntimeGlbLoader`：用工程里已有的 `com.unity.cloud.gltfast` 6.6.0 从 bytes 加载。加载后做**归一化**：
  - 按包围盒缩放到这个用途的目标尺寸（尺寸由用途决定，不信返回值）；
  - 朝向规则：可站立的东西（船、桥、台）把最薄的轴转成竖直方向；摆件和食物底面朝下；
  - 贴地，加碰撞：可踩的用简化 BoxCollider 组合，其余用一个 Box；
  - 贴图降到 1024（WebGL 下必须做，否则显存会爆，参考 `GlbTextureCompressor` 的做法）；
  - 换上和场景一致的 URP 材质参数（参考 `TownLookdev` / `WarmTownPalette`），避免一件特别亮或特别暗。
- `Lux3DCache`：生成结果存 `Application.persistentDataPath/lux3d/<hash>.glb`（WebGL 下这个路径自动落在 IndexedDB）；同一 prompt 第二次直接用缓存，不扣积分。
- **"先保底再替换"组件 `SwapInPlaceholder`**：先在位置上放保底模型，玩法立即生效；生成好以后在原位置做一次"纸片翻飞 / 墨水晕开"的替换特效（≤0.8 s）换成新模型。功能组件（碰撞、交互、踏板）挂在父节点上，换模型不影响玩法。生成期间保底模型上方飘一个小小的旋转邮票，表示"还在送"。

**保底库**（新建 `Assets/TideTown/Resources/Lux3DLibrary/` + `library.json`）
- 每条：`{id, keywords[], category, glb, targetSize, walkable}`。
- 现有场景里的 Lux3D 模型（柴火捆、红球、油壶、浮箱、长椅、台秤……）直接登记，不用新生成。
- **需要新生成的保底**（约 14 次积分）：香烤肉骨头、奶油蛋糕、发光飞盘、小黄鸭、大黄鸭浮船、海龟背壳浮台、星空海螺八音盒、招财橘猫雕塑、干柴火捆、湿柴火捆（或用现有柴火捆改材质，能改就不生成）、小木船、小木尺（E 用）、铜铃（若现有 A5 门铃能用就不生成）、空玻璃瓶（G 用）。生成前先列清单给自己核对，能复用的一律复用。
- 生成用脚本 `tools/lux3d_pregen.mjs`（可以参考 `Documents\say-and-slay\lux3d-test\test.mjs`，用 `--check` 先验 key，不花积分），产物经 `GlbTextureCompressor` 同样流程压贴图，导入工程。

**积分分配建议（共 30）**：保底库 ≤14，D 拼字组合 ≤4，实时链路真机验证 ≤6（Windows dev 直连 3 次、style 对比 2 次、超时 / 失败路径 1 次），机动 ≥6。

### WP-D 信纸揭字成物 + 拼字（最高优先级）

**现状**：`WordMaterializerSystem` 拖拽撕字、抛物线、落点预览都有，手感基础不错。问题有三个：落地后直接改旗标跳关；没有拼字；不调 Lux3D。

**目标**：信上的字是道具。撕下来扔出去，变成实物；两个字拼起来，变出新东西。

**做法**
1. **字签改成"给物品"，不再"给结局"**：
   - 「柴火捆」落在烤炉附近 → 变成一捆**湿柴**（湿润发暗的材质 + 滴水粒子）。可以塞进炉膛，但点火只会冒白烟，点不着（新状态 `wood_wet`）。
   - 「最后一炉暖火」改成一团漂浮的小火苗，可以当火种（代替火柴），但必须有**干柴**才能点着。
   - 「最喜欢的球」落地就是一颗真红球，可以捡起来，但仍要开爪印木匣（或用心愿造物笺 / 残影的替代解法），不能直接唤出小黑。
   - 「煤油壶」→ 一只油壶道具，等于拿到了油，只省掉跑去船棚那一步。
   - 删掉所有"落地即把整站设为完成"的分支（`ApplyThrownWordStoryEffect` 里 fire / ball 两段）。
2. **拼字**：在信纸上把一张字签拖到另一张上，两张合成一张"组合字签"（有合并动画，两张纸签叠在一起盖个邮戳）。规则表 `word_combos.json`：
   - `干 + 柴火捆 → 干柴火捆`：能点着的柴。「干」放进阿萤（学校）的信里，比如"把衣服晒**干**"那一句。
   - `木 + 船 → 小木船`：扔到渡口海面变成可踩的小船，是第 4 种过海方法。「木」放林阿婆的信，「船」放老陈的信。
   - `暖 + 灯 → 街角暖灯`（沿用现有路灯模型，结局用）。
   - 不在表里的组合 → 当成"纪念物"：实时 Lux3D 生成，放在最近的心愿展台上，没有玩法功能，不会坏事。
   - 单字签用不同纸色区分（单字是邮票小方块），让玩家看得出"这个可以拼"。
   - 改信件正文时**只在原句里替换或加粗某个字**，不改剧情意思；改过的句子列进 progress。
3. **接 Lux3D**：每次扔字签都走 `SwapInPlaceholder`：保底模型立即落地生效；同时用 prompt「<字签词> + 这封信的情境 + 手绘温暖小镇风格」提交生成。生成好就原位替换，同一个词这一局只生成一次（缓存）。每局实时生成次数受 `maxPerSession` 限制，超过就只用保底。
4. 同一个词世界里最多一份，再扔一次会把旧的收回（防止刷满地）。字签用完不消失，避免卡关。

**文件**：`WordMaterializerSystem.cs`（主改）、`StoryDirector.Bakery.cs`（加 `wood_wet` / 干柴分支）、信件文本所在的 Story 数据（`*Data.cs` 或 `Resources/World/*.json`，先找清楚在哪）、新 `word_combos.json`、`BakeryEffects.cs`（湿柴白烟）。

**验收**
- 审计：扔湿柴 → 点火失败；拼「干柴火捆」→ 点火成功；`木 + 船` 在渡口变出可走的船，走到对岸（route 检查过）。
- 不在表里的组合 → 心愿展台出现纪念物，主线旗标不变。
- 每种落地都有画面和声音反馈，不靠 Toast。
- story 22/22 不变（经典路线完全不受影响）。

### WP-F 潮汐残影

**现状**：只记位置、来回乒乓播放、没有动作；"协力"是写死的距离特判。

**目标**：按一下怀表，"10 秒前的你"从 10 秒前的位置出现，**原样重演**那 10 秒（走、跳、按住 E、站在踏板上），然后消散。残影能真实地压住踏板、按住机关。

**做法**
1. **滚动录制**：怀表一直在后台记最近 10 s，每 0.05 s 一帧：位置、朝向、移动速度、是否着地、当前动作 / 表情、手里拿的东西、这一帧的互动事件（按下 / 按住 / 松开 E，以及目标 id）。按 R 不再"开始录制"，而是直接召唤。
2. **残影木偶 `EchoPuppet`**：复制 EGGBOY 的视觉层级（保留网格和动画驱动，去掉输入和物理），用录下的速度、着地、动作去驱动**同一套**动作系统（先读 `EggboyPlayer` 怎么播走跑跳，复用它的动画入口，不要只插值位置）。材质换成半透明暖金色 + 菲涅尔边光，脚下留淡淡的水渍脚印。只播放一遍，最后定住 1.5 s，然后化成水花消散。冷却 3 s。
3. **残影能触发的东西用通用组件，不写特判**：
   - `PressurePlate`：检测玩家或残影的碰撞体在板上 → 机关动。
   - `HoldInteractable`：需要"有人按住 E"的机关（绞盘、风箱），残影重演按住事件时也算。
   - 删掉 `AssistNearbyStationTask` 里的距离特判。
4. **两个必做双人机关**（各做成一题多解里的一解，不是主线必经）：
   - **渡口吊桥**：左岸浮板 `PressurePlate` 控制右边吊桥升起。两处距离要比 10 s 内能跑到的距离短，但一个人做不到"同时"。做法：先站浮板几秒，跑到吊桥口，按 R，残影站上浮板，桥升起。
   - **面包店风箱 + 接火**：后院风箱是 `HoldInteractable`，拉住时炉口喷出火苗 3 s；炉膛前的人这时按 E"接火"，炉火直接到最旺，炊烟笔直上升，解锁成就"炉火纯青"。
   - 选做（时间够再做）：学校操场，残影把红球扔出去，现在的你在半空中接住。
5. 残影和 WP-03 联动：渡口卡住 90 s 时，小黑会跑去浮板上蹲一下又跑开（暗示要有人站在那里）。

**文件**：`TidalEchoCloneSystem.cs`（重写播放部分）、新增 `EchoPuppet.cs`、`PressurePlate.cs`、`HoldInteractable.cs`、`WorldMechanismDirector.cs`（绞盘改用 HoldInteractable）、`BakeryEffects.cs`。

**验收**
- 审计：用脚本喂一段录制好的 10 s 输入，残影站上浮板，吊桥升起，玩家通过，route 检查过。
- 截图 / 短视频：残影走路有腿部动作（不是平移）。
- 残影从不阻挡玩家（残影没有阻挡碰撞，只有触发器）。

### WP-A 三环木匣 + 旧物暗格

**现状**：`ObjectInspectModal`（39 KB）和 `WoodenMechanismPuzzleModal`（31 KB）逻辑比较完整：三连木栓、三环联动、错 3 次反震。问题主要在操作手感和"弹窗感"。WP-01 要具体确认哪些地方是按钮、哪些是 3D。

**做法**

### WP-B 海风重心

**现状**：`TidalWindChallenge` 逻辑有：Shift 压低、连按空格、失衡惩罚、掉东西。但大量说明文字（"【危险！…失衡度 %】"），惩罚是吹回起点，挫败感强。

**目标**：风来之前看得到、听得到；稳住了有奖励；失败了有点狼狈，但不至于太折磨人。

**做法**
1. 预警（风到前 1.5 s）：海面卷起白色风线（3D 粒子带，从海那边扫过来），旗子和树猛摆，风声变大，EGGBOY 天线被吹弯、换"紧张"表情。
2. 稳住：按住 Shift → EGGBOY 蹲低前倾（复用姿态层）；风过后自动触发 3 s"顺风冲刺"（速度 ×1.6，身后拖风线），这是奖励。
3. 失败：踉跄后退 2–3 m（不是回起点），手里的东西掉出去，**物理滚动**到附近一个能捡到的位置，掉进水里就漂到最近的岸边（复用 `FloatingCrate` 的漂浮）。地点限定在迎风走廊和涨潮渡口。
4. 去掉所有失衡度文字。平衡状态用 EGGBOY 的表情和身体倾斜表现；屏幕最多在脚下加一个很淡的弧形平衡指示（可选）。
5. 麦克风吹气 = 额外稳定加成，保留。

**验收**：迎风走廊录一段"预警 → 稳住 → 冲刺"和一段"失败 → 掉东西 → 捡回"；water 和 route 审计不变。

### WP-E 透视拓印（重做量最大）

**现状**：没有透视。卡片上选一个模板，按固定倍率（1.8–5.5）放在人前方 3.4 m。

**目标**：真正的透视借位：拿在手里的小物件在取景框里看起来多大，按下快门以后在世界里就变成那么大（Superliminal 规则）。

**做法**
1. 按 C 进入取景框：镜头切到 EGGBOY 眼睛高度的第一人称，画面加一个复古取景框边框，四周暗角，有快门音效。手里的物件来自邮包里收集到的小物件，用 Q / Z 切换，起始至少 3 件：小木尺、旧拖鞋、微缩船模；后续可以加铜门铃。物件放在镜头前 `d_hold`（约 0.6 m）。
2. 透视规则：从镜头中心射线打到世界表面，命中距离 `d_hit`。按快门时，物件放到命中点，`缩放 = 手持缩放 × d_hit / d_hold`，朝向保持取景框里看到的样子，所以屏幕上的大小和角度完全不变，"变真"的那一瞬间没有跳变。有缩放上限（例如最长边 ≤12 m），超过就不能拍，框变红。
3. **拓印插座 `PrintSocket`**：在世界里摆 2 个必做插座：
   - 一处断开的石桥 / 断崖（找一处不在主线上的近路，或者给渡口加一段断桥作为第 5 种过海方法；选址要过 route_check）；
   - 灯塔外侧一段高台的近路。
   - 插座有两个端点，放下的物件包围盒同时盖住两个端点（容差 0.4 m）就吸附摆正，变成可走；否则照样放下，但只是装饰，可以再拍走（取景框对准它按右键收回）。
4. 选做：铜门铃对准灯塔顶放大成巨钟，敲一下（按 E），海雾散开。只是表演，要控制性能。
5. 世界里同时最多存在 3 个拓印物，多了自动收回最早的。放大后的碰撞用简化 Box 组合，不用 MeshCollider。
6. 删掉模板卡片 UI，只留取景框边角的小字：物件名 + 当前倍率。

**文件**：`PerspectivePrintSystem.cs`（基本重写）、新 `PrintSocket.cs`、场景摆放走 `IslandBuilder`（不要手改 .unity 后忘了让生成器知道）。

### WP-G 光影 + 声音

**现状**：光影是两个模型在镜头前转，角度近 0° 就算赢，没有影子；声音是 4 个按钮放程序合成音。

**目标**：转动真实的灯，让杂物在墙上投出真实的影子，拼出一把钥匙；去岛上收集真实的声音，按乐谱放出来。

**做法（光影）**
1. 选一面墙（推荐灯塔下船棚的内墙或侧墙，离灯塔近、主题相关，选址不能挡主线），墙前摆一堆杂物（现有的木箱、铁架、渔网、油壶等 Lux3D 模型）。
2. 一盏可以转的提灯（或探照灯）放在支架上，`HoldInteractable`：按住 E 用鼠标 / 摇杆转灯的方向和高度。用 URP 真阴影（聚光灯 + 软阴影），墙上就是真实的影子。
3. 目标形状：钥匙。在目标姿态下，杂物的影子要**真的**拼成钥匙轮廓。先摆好杂物、找到目标灯角，截图确认形状一眼能看懂；判定用"灯角在目标附近 ±6°"，确定性强，好测。
4. 对上时，墙上的影子钥匙"实体化"（影子区域发光 → 墙里的暗门往里打开），里面有一件奖励物，比如第 3 只漂流瓶，或者一只装着声音的空瓶。
5. 选做：第二个形状"飞鸟"，对上后一只纸鸟从墙上飞出来，带路去下一处线索。

**做法（声音）**
1. 拿到空玻璃瓶后，靠近四个声源按 E 装声音：面包店铜铃、学校秋千吱呀、小黑汪汪、柴堆劈柴。声音在世界里本来就会响（风吹铃响、秋千被风推动），瓶子装满会变成对应颜色并发光。
2. 乐谱：画在学校黑板角落（四个符号的顺序），作为环境线索。
3. 中央广场喷泉旁放一个八音盒底座，按 E 放瓶子；顺序对了，广场周围几栋房子随节拍上下起伏、旋转小角度，像八音盒一样，持续约 10 s 后**精确复位**（动画结束要把 transform 恢复原值，碰撞不能变），喷泉喷出一圈光。
4. 声音用 `AudioClip` 播放。如果找不到合适的现成音频，用程序合成（铃：衰减正弦叠加；秋千：滤波噪声扫频；狗叫：两段带包络的方波 + 噪声；劈柴：噪声冲击），合成效果写进证据给用户确认。不要从网上下载音频。

**文件**：`ShadowAndChimeSystem.cs`（重写，拆成 `ShadowLanternPuzzle.cs` 和 `SoundBottleSystem.cs`）、场景摆放走 `IslandBuilder`。

**验收**：审计把灯转到目标角，暗门打开；放 4 瓶声音，房子起伏后位置和旋转与动画前误差 < 1 mm、< 0.1°；墙上影子截图能认出是钥匙（人工确认，放进证据）。

## 附录 B · 前人踩过的坑（来自之前几轮）

- Unity 退出时偶尔挂住：`run-audit.ps1` 已处理（结果写完 15 s 后强关），不要当成失败。
